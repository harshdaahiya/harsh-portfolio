# Project Setup & Folder Structure Guide

This document explains the architecture and folder structure of this Next.js project. You can use this as a reference or provide it to an AI assistant to set up a new Next.js project following the exact same conventions.

## Tech Stack Overview

The project is built with a modern React ecosystem:

- **Framework:** Next.js (App Router, v15+) with React 19.
- **Styling:** Tailwind CSS v4.
- **UI Components:** Radix UI primitives and Shadcn UI (configured via `components.json`).
- **Animations:** Framer Motion (`motion`) and Lenis for smooth scrolling.
- **Icons:** `lucide-react` and `react-icons`.
- **Forms & Validation:** `react-hook-form` and `zod`.
- **Email:** `resend`.
- **Code Quality & Tooling:**
  - TypeScript (strict mode)
  - ESLint (Flat config `eslint.config.mjs`) & Prettier
  - Husky, `lint-staged`, and Commitlint for Git hooks
  - Knip (`knip.json`) for detecting unused files, dependencies, and exports.

## Root Directory Configuration

The root directory contains essential configuration files:

- **`.env` / `.env.local`**: Environment variables.
- **`next.config.ts`**: Next.js configuration in TypeScript.
- **`components.json`**: Configuration for Shadcn UI components.
- **`eslint.config.mjs` & `.prettierrc`**: Linting and formatting rules.
- **`commitlint.config.mjs`**: Enforces conventional commits.
- **`lint-staged.config.mjs`**: Runs linters on git staged files.
- **`knip.json`**: Configuration for Knip dependency auditing.
- **`tsconfig.json`**: TypeScript configuration.

## The `src/` Directory Architecture

All application code resides inside the `src/` folder. It is modularized by technical concern and feature domain.

### 1. `src/app/` (Next.js App Router)

Handles the routing and pages of the application.

- Contains the main `layout.tsx` and `page.tsx` (Home page).
- **Global Styles:** `globals.css` is located here, containing Tailwind imports and global CSS variables for Shadcn UI.
- **Routes:** Folders like `blog/`, `contact/`, `experience/`, `projects/`, and `resume/` represent individual pages/routes. Each contains its own `page.tsx` (and optionally `layout.tsx` or `loading.tsx`).

### 2. `src/components/` (UI & Feature Components)

Components are deeply organized by feature/domain rather than grouping everything into a flat folder.

- **`ui/`**: Base UI components (typically generated by Shadcn UI like buttons, dialogs, inputs). These are highly reusable.
- **`layout/`**: Structural components like Header, Footer, Navigation bars, and layout wrappers.
- **Feature Folders (e.g., `landing/`, `contact/`, `experience/`, `projects/`, `resume/`)**: Components specific to certain pages or features.
- **`sections/`**: Larger composite components that make up sections of a page (e.g., HeroSection, AboutSection).
- **`common/`**: Shared components used across multiple features (e.g., generic cards, typography wrappers).
- **`lucide-icons/` / `react-icons/` / `svgs/`**: Wrappers for icons and custom SVGs.
- **`analytics/`**: Components for tracking and analytics (e.g., Vercel Analytics, Google Analytics scripts).

### 3. `src/actions/` (Server Actions)

Contains Next.js Server Actions. These are asynchronous functions that run on the server, typically used for form submissions, data mutations, or API interactions (e.g., sending emails via Resend).

### 4. `src/config/` (Application Configuration)

Holds static configurations, constants, navigation links, site metadata, and settings.

- Example: `Experience.tsx` (contains static data or configurations for the experience section).
- Site config objects (title, description, URL, social links).

### 5. `src/data/` (Static Data)

JSON files or TypeScript files exporting static data objects used throughout the site (e.g., a list of blog posts, project details, or resume data) that don't come from an external API or database.

### 6. `src/emails/` (Email Templates)

React components used as email templates. These are compiled to HTML and sent using the Resend SDK.

### 7. `src/hooks/` (Custom React Hooks)

Reusable React hooks (e.g., `useMediaQuery`, `useScroll`, `useTheme`).

### 8. `src/lib/` (Utilities & Helpers)

Utility functions, API clients, and shared helper logic.

- **`utils.ts`**: Crucial file containing the `cn()` utility (combining `clsx` and `tailwind-merge`) used extensively by Shadcn UI components.

### 9. `src/types/` (TypeScript Definitions)

Global TypeScript interfaces and type aliases used across the application. Ensures type safety for data models and component props.

## Instructions for AI: Setting up a New Project

If you are an AI tasked with creating a new Next.js project using this structure, follow these steps:

1. **Initialize Next.js:** Run `npx create-next-app@latest . --typescript --tailwind --eslint --app --src-dir --import-alias "@/*"`
2. **Install Core Dependencies:**
   - UI/Styling: `npm i class-variance-authority clsx tailwind-merge lucide-react motion lenis`
   - Forms: `npm i react-hook-form @hookform/resolvers zod`
3. **Initialize Shadcn UI:**
   - Run `npx shadcn@latest init` (Set style to Default/New York, base color to Slate/Zinc, and global CSS to `src/app/globals.css`).
4. **Scaffold the `src/` Directory:**
   - Create the missing directories: `mkdir -p src/actions src/components/{ui,layout,common,sections} src/config src/data src/emails src/hooks src/lib src/types`.
5. **Add the `lib/utils.ts` helper:** Ensure `cn` function is present.
6. **Set up Code Quality Tools (Optional but recommended):**
   - Install Husky, lint-staged, commitlint, and prettier.
7. **Begin Feature Development:** Create components within their respective feature folders in `src/components/` and assemble them in `src/app/` routes.
